# 资深全栈工程师直求简历规则设计

## 目标

将新发布的资深全栈岗位纳入与 AI 产品经理相同的跨平台直求简历流程。候选人无论提出什么问题，当前均不发送答复、不执行筛选，只推进简历获取。

## 名称规则

- 规则名称统一为 `资深全栈工程师`。
- 简历入库、统计和简历库标签统一为 `全栈工程师`。
- 当前平台标题包括：
  - BOSS：`资深全栈工程师（AI 原生 B2B 平台 ）`
  - 51job：`资深全栈工程师（AI 原生 B2B 平台 / 工程 Owner）`
  - 智联：`资深全栈工程师（AI 原生 B2B 平台 / 工程 Owner）`
- 匹配时复用现有岗位名称规范化逻辑，兼容空格、全半角括号、斜杠和 `Owner` 周边空格差异。
- 只匹配以 `资深全栈工程师` 为核心的已知标题和紧凑形式，不把任意普通 `全栈工程师` 岗位自动归入该规则，避免误伤未来岗位。

## 处理行为

- BOSS、51job、智联均启用 `directResume`。
- 不发送筛选问题。
- 不回答岗位、薪资、工作方式、面试方式或其他候选人问题。
- 未收到简历且未发起过求简历时，从现有两句求简历前置话术中随机选择一句，再执行平台原生求简历动作。
- 已收到简历或已发起过求简历时不重复发送话术、不重复求简历。
- 候选人主动提出发送简历时，直接进入平台原生简历获取流程。
- BOSS 以求简历动作验证成功作为业务简历获取完成；51job 和智联继续沿用各自现有下载与入库流程。

## 实现范围

- 在共享岗位规则配置中增加资深全栈工程师规则及平台标题别名。
- 在跨平台直求简历策略集合中加入 `全栈工程师`，保证三个 runner 均发送前置话术并进入求简历动作。
- 不增加新的知识库答案，不修改其他岗位的处理策略。
- 不修改 JD 评分规则；本次只保证入库标签为 `全栈工程师`。

## 测试

- 规则解析测试覆盖 BOSS 短标题、51job/智联长标题和紧凑标题形式。
- 三个平台分别验证：候选人提出问题时不回复，决策仍为直求简历。
- 验证 `resumeJobType` 为 `全栈工程师`。
- 验证普通 `全栈工程师` 文本不会因过宽别名意外命中资深岗位规则。
- 运行现有 BOSS、51job、智联直求简历回归测试，确保 AI 产品经理等已有岗位行为不变。
